# Intuition

We need to list all patients who have a specific medical condition, identified by the presence of that condition name as a standalone word (not just a substring) in their `conditions` field. The `conditions` field stores multiple condition codes/labels in a space-separated format, so we must carefully match whole tokens instead of simple substrings.

## Approach

- **Understand the schema**: The `Patients` table contains, among other fields, a `conditions` column that is a space-separated list of condition codes/labels like `'DIAB1 HYPT'`.
- **Whole-word matching**: To ensure we only match patients who actually have the target condition (e.g., `'DIAB1'`), we should treat the `conditions` string as delimited by spaces and avoid partial matches (e.g., `'DIAB10'` should not match `'DIAB1'`).
- **Use boundary-aware pattern**: In SQL dialects that support regular expressions, we can use word-boundary or explicit space-boundary patterns around the target condition.
- **Filter on condition**: Once the pattern is defined, we simply filter the `Patients` records using `WHERE` to keep only those with the desired condition.
- **Projection**: Select the requested columns (typically the patient ID and medical conditions or name, depending on the problem statement).

## Complexity

- **Time complexity**: \(O(N)\), where \(N\) is the number of patients, since we scan each row’s `conditions` string once.
- **Space complexity**: \(O(1)\) extra space, aside from the output, because we do an in-place filter using a single pass over the table.

## Edge Cases

- **Condition at the beginning or end**: The target condition might be the first token, the last token, or the only token in `conditions`.
- **Multiple spaces**: Extra spaces between tokens or at string boundaries should not break the logic (depending on the dataset; robust patterns generally handle this).
- **Substring pitfalls**: Patients whose `conditions` include codes that only *contain* the target condition as a substring must not be returned.
- **No matching patients**: The query should simply return an empty result set without errors.

## Code

```sql
-- PostgresQL
SELECT * 
FROM Patients p
WHERE conditions
LIKE '% DIAB1%'
OR conditions
LIKE 'DIAB1%'
```
